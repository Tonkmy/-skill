# 设计理念

用户定的四条，优先级最高。设计和其他资料冲突时，以这里为准。每条都写了原话、自检问题和对应的方法。最后一节「隐含偏好」来自对话，还没升级成正式条目。

## 1. 有成长，有推进

- **原话**：「有成长有推进」
- **含义**：玩家能看见自己在变强，而且每隔一小段就有一次看得见的跃升，比如换住处、换衣服、升职、开店、剧情翻篇。
- **自检**：
  - 随便停在哪一旬，玩家能说出「再过几旬我就能 ___」吗？
  - 大目标之间的间隔，是不是都在「当时收入的 4–10 旬」？（economy.md）
  - 后期还有成长感吗？还是钱多到没处花了？
- **方法**：[systems.md](playbook/systems.md) 里的成长阶梯、住所阶梯、换装＝数值；[economy.md](playbook/economy.md) 里的目标间隔。

## 2. 简单，系统不能太复杂

- **原话**：「简单，系统不能太复杂」
- **含义**：核心循环一句话说得清，每个系统都有自己独有的用处。宁可少做一个系统，把剩下的调平。
- **自检**：
  - 核心循环能写成一句话吗？（例：打工挣钱 → 升属性解锁更好的活 → 攒钱换住处 → 解锁新玩法）
  - 每个系统能用一句话说出它「别的系统替代不了」的作用吗？说不出来就砍或者合并。
  - 新玩家要读多少字才会玩？界面上同时可点的按钮多不多？
- **方法**：新系统先写成 systems.md 里的模式卡，写不出「解决什么」就别做。

## 3. 有主线，以免不知道干什么

- **原话**：「有主线，以免不知道干什么，承担指引工作」
- **含义**：主线既是故事，也是新手引导和目标列表。任何时刻，玩家都知道下一步做什么。
- **自检**：
  - 界面上有没有「当前目标」？
  - 主线节拍表是不是覆盖了全程，从开局一直到结局？
  - 有结局吗？结局是否回扣开局的处境？
- **方法**：[narrative.md](playbook/narrative.md) 的主线骨架和节拍表；[skeleton.md](playbook/skeleton.md) 的目标栏。

## 4. 丰富玩法和细节，贴图、音乐等

- **原话**：「丰富玩法和细节，贴图音乐等」
- **含义**：系统少，但每个系统都有细节：文案、贴图、音乐、音效、角色小动作。简单的骨架靠细节撑出丰富感。
- **自检**：
  - 主要场景有没有背景图，有没有昼夜变化？主角和主要角色有没有立绘？
  - 关键剧情（每个男主的最后一段、各个结局）有没有 CG？
  - 不同场景、不同情绪有没有不同的 BGM？
  - 同一个系统事件，是不是每个角色各有一版台词？
- **方法**：[assets.md](playbook/assets.md) 的素材清单；narrative.md 的台词矩阵。

## 隐含偏好（来自对话，未升级）

- 做**女性向**，要**能赚钱、有爽点**（2026-10-29）。
- 物价和数值要**参考优质独立经营游戏**来设计，不能拍脑袋（2026-10-29）。
- 资料要能**复用**，按 agent engineering 的方式当成外部记忆和数据库维护（2026-10-29）。
